== Finding: the default OpenMP build does not import on Debian/Ubuntu (no LDFLAGS)
Builds 'fix' and 'base' with the CI command and no LDFLAGS:
fix import: /work/venv-fix/bin/python: symbol lookup error: /work/venv-fix/lib/python3.11/site-packages/uedge/bbbpy.cpython-311-x86_64-linux-gnu.so: undefined symbol: GOMP_parallel
base import: /work/venv-base/bin/python: symbol lookup error: /work/venv-base/lib/python3.11/site-packages/uedge/bbbpy.cpython-311-x86_64-linux-gnu.so: undefined symbol: GOMP_parallel
Cause: Forthon links each package extension (bbbpy, ppppy, apipy, ...) without -fopenmp/-lgomp; only uedgeC gets
-fopenmp, and Debian/Ubuntu gcc link with --as-needed (gcc -dumpspecs), so libgomp is dropped from uedgeC too.
bbbpy link line (base build): gcc -shared -L/usr/lib/gcc/x86_64-linux-gnu/12 -L/usr/lib/gcc/x86_64-linux-gnu/12/../../../x86_64-linux-gnu -L/usr/local/lib -lgfortran -lmvec -lreadline -o build/lib.linux-x86_64-cpython-311/uedge/bbbpy.cpython-311-x86_64-linux-gnu.so -Wl,-z,lazy
Ubuntu 24.04 (gcc 13.3.0-6ubuntu2~24.04.1, Python 3.12), same command, no LDFLAGS:
(console output of the check, not saved to a log) /work/venv-fix/bin/python: symbol lookup error: /work/venv-fix/lib/python3.12/site-packages/uedge/bbbpy.cpython-312-x86_64-linux-gnu.so: undefined symbol: GOMP_parallel
Workaround used for every build below: LDFLAGS=-fopenmp (bbbpy, ppppy, apipy then NEED libgomp.so.1).
