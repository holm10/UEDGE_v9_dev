## 1. Executive Summary

UEDGE v9 is about to be cut down and restructured: dead options removed, and the monolithic `pandf` tree split and
simplified. CLAUDE.md requires that refactors leave default results unchanged to round-off. The only regression evidence
today is the external `upstream/pytests` branch, which has three problems:

- It holds 163 near-copies of 8x4 cases: 129 MB, of which 89 % is duplicated `solution.h5` files.
- Each case passes or fails on a single scalar `fnrm` at `rtol=1e-5`.
- It fails in CI on every non-master branch. `build-test-wheel.yml:57-65` checks out a `pytests-develop` branch that
  does not exist upstream.

This epic builds a small regression suite inside this repo. It protects the **full RHS vector `yldot`**: every equation
at every cell, produced by `pandf` (`bbb/pandf.m:513`).

`yldot` is a deterministic function of the state vector `yl` and the input variables. Phase 1 must confirm this for
every family; the old suite's own comments hint at history dependence. The suite is built on that property:

- Each **family** is a committed converged state, perturbed by a few percent.
- Each family is evaluated once in its default configuration.
- It is then evaluated once per **input variable**, with that variable changed and everything else left alone
  (one-factor-at-a-time, "OFAT").
- Every variable tagged `+input` or `+maybeinput` in the `.v` files is one test (968 effective tags today).
- Coverage therefore grows linearly with the number of inputs, not combinatorially.

There are two kinds of family:

- **Small families** come from the clean template states already on `upstream/pytests`: D-only, D with molecules, D+C,
  orthogonal, and a 32x17 slab with potential and E×B drift. They store full reference vectors, so a failure points to
  the exact cell.
- **One large family** is the epic owner's converged, well-resolved 100x50 D+D2+C case. It keeps X-point, cut, plate and
  separatrix cells apart and represents production runs. It stores projection "sketches" whose size does not depend on
  the grid.

A **locality check** records how the local Jacobian evaluation `pandf(xc,yc,...)` differs from the full evaluation, and
asserts that this pattern does not change. That protects the `initialize_ranges` loop-range logic that refactors break
most easily.

**MVP goal:** any change to `yldot` that a refactor of the `pandf` tree makes visible *in the tested configurations*
(six families × OFAT variants) is detected in CI on the PR that introduces it. The failure is localized to input
variable, equation, species and cell (or region, for the large family). Committed test data stays within about 30 MB,
so that `upstream/pytests` can be retired.

## 2. Mission

Give every UEDGE refactor a fast, trustworthy "old vs new" answer: *did `yldot` change, and where?*

**Core principles**

1. **Old-vs-new equivalence, not physics validation.** The suite proves a change did not alter results. It does not
   prove the physics is right. Manufactured solutions and conservation checks are a separate future epic.
2. **Linear coverage.** One test per input variable per family; no permutation testing.
3. **Small, self-contained data.** Base states, grids, rate files and references live in this repo, with one reference
   file per family. There is no external test branch.
4. **Component-wise comparison with measured tolerances.** Compare `yldot` component by component (or by sketches for
   the large family), never as a scalar norm. Tolerances come from measured round-off spread.
5. **Failures explain themselves.** A failure names the variant, equation, species, cell or region, and the size of the
   difference.

## 4. MVP Scope

### Core functionality
- ✅ **Python test harness** in this repo (`tests/`). It does five things:
  1. loads a base state;
  2. applies the input configuration;
  3. runs a non-iterating `bbb.exmain()`;
  4. evaluates `yldot` through the Python-callable `bbb.pandf(-1,-1,neq,t,yl,yldot)` (`bbb/bbb.v:3377`);
  5. compares the result with stored references.

  The protocol is in §6.
- ✅ **Small families**, built from the clean `templates/` states and assembled `input.py` files on `upstream/pytests`
  (commit `b535508`):

  | Family | Source on `upstream/pytests` | Physics | Grid |
  |---|---|---|---|
  | `d_only` | `templates/grids/nonog` + `unittests/D_only/nonog/default/input.py` | D+, D0 (inertial), `isphion=1`, non-orthogonal snull | 8x4 |
  | `d_mols` | `templates/grids/nonog_mols` + `unittests/D_mols/nonog_mols/default/input.py` | as `d_only` + D2 (`ishymol=1`) | 8x4 |
  | `d_c` | `templates/fulltests/nonog_d_c-fb_16x8` | D + 6 C charge states (`isimpon=6`, `C_rates.strahl`) | 16x8 |
  | `ortho` | `templates/fulltests/orthogonal_unittest` | D, `isphion=1`, orthogonal grid | 8x4 |
  | `slab_phi` | `templates/grids/slab` + `unittests/slab_D_only/slab/default/input.py` | D, potential/currents (`isphion=1`), E×B drift (`cfyef=0.6`), generated slab grid | 32x17 |

- ✅ **One large family `large_dd2c`.** It is the epic owner's converged complex case, about 100x50: D ions and atoms,
  D2 molecules, and multi-charge-state carbon, plus drifts and potential if the case has them.
  - It is committed as supplied, with no regridding, interpolation or reconvergence.
  - It is the family with distinct X-point, cut, plate and separatrix cells on a production-like grid (see §7.1).
- ✅ **Base state for every family:** the converged state plus a **seeded perturbation of a few percent**. It is stored as
  physical arrays (`nis, ups, tes, tis, ngs, tgs, phis, tipers`), not as a seed. The **unperturbed converged state**
  is stored too, also as physical arrays (`converged_state.h5`). It is used for the `timestep` configuration (§6) and
  the OpenMP/Jacobian check (§7.7).
- ✅ **Default test:** for every family, the full `yldot` is compared component by component. This is the pass/fail
  assertion. Intermediate module arrays are stored too, but are used only as diagnostics for localization.
- ✅ **OFAT variant sweep** over every effective `+input`/`+maybeinput` variable in all `.v` files, on every family.
  Each variant is varied from the family's own value, and the exact value applied is recorded. Each variant is
  classified SENSITIVE, INERT, INVALID or EXCLUDED, and that class is asserted (§7.2).
- ✅ **Two reference stores behind one interface:**
  - **Full vectors** for small families, with each variant stored as a sparse difference from the default.
  - **Projection sketches** for the large family, per block (equation × species × region), plus the full default
    `yldot`.
- ✅ **One reference file per family** (`references/<family>.h5`), plus a text manifest
  (`references/<family>.manifest.json`) whose diff shows which variants changed.
- ✅ **Locality check:** compares the local `pandf(xc,yc)` result with the full evaluation, following `jac_calc`'s
  protocol (§7.5). The mismatch pattern is stored as a reference and asserted unchanged.
- ✅ **Reference generator:** builds references from a named git commit in a separate build, and records the commit,
  compiler, flags and platform. Committed references are produced in a CI workflow on the pinned runner image.
- ✅ **Round-off and history measurement:** a Phase 1 experiment that sets the tolerances and the warm-up protocol.
- ✅ **Mutation set:** committed mutation patches and a runner that prove the suite detects seeded faults.

### Technical
- ✅ Per-equation tolerances come from measurement:
  - the same build run twice;
  - `-O0` (no FPE traps) against `-O3`;
  - serial against OpenMP with 1 and N threads;
  - macOS against Linux.
- ✅ **Per-variant isolation.** A forkserver preloads `uedge`, then forks one child per variant. The child runs the
  family's `input.py` and the variant (§6). Every child gets a timeout, and a crash or timeout is classified, not fatal.
  Isolation is needed because Forthon module state is global and `xerrab` aborts through `kaboom`
  (`com/error.f:1-13`).
- ✅ **Bounds-check audit.** At full reference regeneration, a `--checkbounds` build (`setup.py:741-745`) classifies
  variants that index out of bounds as INVALID.
- ✅ **CI build once, test sharded.** One job builds the serial wheel. Test jobs, sharded per family, install it.
- ✅ **Data budget:** at most 30 MB of committed test data in the working tree, with a size cap per family. Growth of git
  history is monitored (§7.3).

### Integration
- ✅ **PR tier.** `build-test-wheel.yml` runs this tier on every PR in place of the `LLNL/UEDGE@pytests` checkout. It
  covers:
  - all small families: default, full sweep, and the locality check in the default configuration;
  - the large family's default test only.
- ✅ **Nightly tier.** A scheduled workflow runs it nightly. It also runs on every PR except those that only touch
  documentation or the AI layer. The filter is `paths-ignore`: `docs/**`, `doc/**`, `.claude/**`, `**/*.md`. It covers:
  - the large family's full sweep;
  - the large family's sampled locality check;
  - the locality check for the `meth*` variants and the locality inputs on all families (§7.5).
- ✅ **Reference-change guard in CI.** It runs on `pull_request_target` events only (opened, synchronize, reopened, edited).
  CI fails when guarded reference data changes, unless one of these holds:
  - the PR description declares `Default results: changed`;
  - the change is an allowed category (§7.6): an addition, a prune of entries that are not SENSITIVE, a rename with
    identical data, or a diagnostics-only change.
- ✅ **Code-facts on the ticket branches,** each with the trailer `AI-layer: code-facts`:
  - `.claude/context/testing.md`;
  - the `CLAUDE.md` Build & validation commands;
  - `.claude/context/branching.md`.
- ✅ **Two AI-layer PRs** on `feature/v9-ai-<slug>` branches, because these are process changes (`branching.md`):
  1. **Adopt**, merged before the Phase 3 CI switch. The new suite is added to these, *alongside* the old one:
     - the `validate`, `execute`, `implement-fix` and `code-review` skills;
     - the `uedge-implementer` agent;

  2. **Retire**, merged after the Phase 4 gate. It removes the old-suite steps from `validate`, `init-project`,

### Deployment / retirement
- ✅ gcov branch-coverage report of `pandf*.F`, comparing the new suite with the old one.
- ✅ Retirement of `upstream/pytests` from the AI layer and from local validation once the Phase 4 gate passes. In CI it

### Out of scope
- ❌ Method of manufactured solutions, conservation and other physics-correctness checks (a new epic).
- ❌ Pairwise or t-way combinatorial testing of option interactions.
- ❌ Coarsening, interpolating or reconverging fine-grid cases to make mid-size ones (considered and dropped).
- ❌ Variants that change the equation layout (`nisp`, `ngsp`, `nhsp`, grid size, `nxcore`, …). Such a change defines a

- ❌ Solver convergence, Newton/Krylov behaviour, time-stepping control (`rundt`), Jacobian *values*, the

- ❌ The OpenMP RHS path (`OMPPandf1Rhs` via `ffun`) and the parallel Jacobian in CI. The suite calls `pandf`

- ❌ Python post-processing, plotting, and save/restore format tests (beyond loading base states).
- ❌ Fixing bugs the suite exposes. Each one becomes its own `bugfix/v9-*` ticket.
- ❌ BASIS tests (`build-basis.yml`), which stay as they are.
- ❌ Hosting references outside git (LFS, release assets) unless the history budget in §7.3 is reached.

## 5. User Stories

1. **As a core developer refactoring `pandf_plasma_energy.m`, I want one command that tells me whether `yldot` changed,
   so that I can refactor with confidence.**
   *Example:* `pytest tests/ -n auto -m "not nightly"` →
   `FAILED d_c::bbb.cfvisx(=1.1): yldot te(e) at (ix,iy)=(5,3) rel diff 3.2e-4 > tol 1e-11; first differing intermediate: feex`.
2. **As a developer planning to remove options, I want a list of inputs that have no visible effect in any family, so
   that I know where to start looking.**
   *Example:* the manifests list `bbb.isfoo` as INERT in all six families.
   - INERT is only a **candidate** signal. The suite never exercised the option's live path, which may need another
     switch to be on.
   - Deleting an option still needs code inspection (grep every use) and the Phase 4 coverage report.
   - What the suite does guarantee is the opposite direction: an input that was SENSITIVE becoming INERT fails the
     test.
3. **As an agent running `validate`, I want a deterministic, machine-readable result, so that I can report ✅/❌ verbatim.**
   *Example:* JUnit XML plus a summary line per family,
   `d_c: 968 variants: 612 sensitive, 301 inert, 41 invalid, 14 excluded; 0 failures`.
4. **As a physics developer adding a new switch `isnewmod` (default off), I want to regenerate only the references that
   change, so that existing references stay untouched.**
   *Example:* `make_references.py --only bbb.isnewmod` adds one manifest entry per family. The guard accepts it
   without a declaration, because it is an addition and every existing guarded SHA is unchanged.
5. **As a reviewer, I want each reference file to record the commit and toolchain that produced it, and the manifest to
   show which variants changed, so that I can verify an intentional reference change.**
6. **As a developer touching `initialize_ranges`, I want the locality check to fail when the local evaluation stops
   agreeing with the full evaluation where it used to agree, so that stencil bugs are caught before they surface as
   convergence problems.**
   *Example:* `large_dd2c locality: column te(41,17): new mismatch rows ni(43,17), up(43,17) not in reference pattern`.
7. **As the project owner, I want to stop carrying the 129 MB external test branch, so that the repository and CI are
   simpler.**

**Technical stories**

8. As a maintainer, I want each equation's tolerance to come from a recorded measurement, so that tolerances are neither
   so loose that they hide bugs nor so tight that they fail on round-off.
9. As a maintainer, I want any run-to-run or within-process history difference on the same build reported as a defect,
   not absorbed into the tolerance.
10. As a developer removing a dead input in a refactor PR, I want a prune command that the reference guard accepts when
    the removed entry was not SENSITIVE, so that removing options does not require "Default results: changed".

## 6. Core Architecture & Patterns

### Evaluation protocol (one variant)

```
environment (set before any import): UEDGE_BANNER=0 (no PyPI version check, src/uedge/_banner.py:42),
                                     OMP_NUM_THREADS=1, OPENBLAS_NUM_THREADS=1
forkserver (one per test process, single-threaded, preloads uedge + numpy)
  └─ child per variant (timeout T_family):
       1. chdir family dir; exec the family input.py verbatim       (it may call bbb.allocate() itself and set
                                                                     dynamic arrays, e.g. d_only sets nwallo/nwalli
                                                                     after its own allocate)
       2. PRE phase: apply variant to scalars and static arrays     (d read live here)
       3. bbb.allocate(); restore base_state.h5 (restart=1)          (harness-owned; replaces the old restore snippet)
       4. POST phase: apply variant to ALL dynamic (_real/_integer) arrays, including "input after alloc" ones
                                                                    (d read live here, after input.py + restore)
       5. issfon=0, ftol=1e50, dtreal=1e20; bbb.exmain() × W         (W = warm-up count fixed in Phase 1)
       6. timestep config only (two-pass):
          a. before step 3's restore, restore converged_state.h5 instead and run exmain once (ftol=1e50);
             copy y_c = bbb.yl[:neq] (packed by UEDGE itself, with the variant applied)
          b. then do steps 3–5 with base_state.h5, setting isyloext=1, yloext[:neq]=y_c before exmain, so exmain
             sets ylodt = y_c itself (bbb/odesolve.m:151, bbb/bbb.v:1311-1312)
          c. after exmain: dtreal=Δt, dtuse[:]=Δt, and the saved state arrays (nis, ups, tes, tis, ngs, tgs, phis)
             = converged_state values (fqydt/cfqydt read the *s arrays, bbb/pandf_potencur.m:217-222; convsr_vo2
             re-derives their face values on every pandf call, bbb/convert.m:858-930)
       7. yl[neq] = -1 (nksol-RHS flag), yl[neq+1] = 0 (nufak)
       8. bbb.pandf(-1,-1,neq,0.,yl,yldot) × P; keep the last        (P fixed in Phase 1)
       9. return yldot (+ diagnostics for the default) through a pipe; exit
compare → class assertion (§7.2) → localization (§7.4)
```

- **Phase rule.** Scalars and static arrays are applied in PRE. Every dynamic array (245 effective tags today) is applied in
  POST. Allocation would otherwise reset or resize them, and the family `input.py` sets some of them after its own
  `allocate()`. `overrides.toml` may force PRE for a dynamic array whose value `allocate` itself reads. The base value
  `d` is read live at the moment of application, and recorded.
- **Family `input.py`, normal form.** It is the case definition only.
  - It sets inputs, and may call `bbb.allocate()` to set dynamic arrays.
  - It **never loads a state**: no assignment to `restart`, no `hdf5_restore(...)` call, no `exmain(...)` call.
    Imports such as `from uedge.hdf5 import hdf5_restore` may stay.
  - For the small families this means:
    - `d_only`, `d_mols`, `slab_phi` and `ortho`: remove the trailing restore snippet (`templates/restore/default.py`;
      in `ortho` at `:105-108`). Mid-file `allocate` calls, such as `ortho:57`, stay.
    - `d_c`: remove `bbb.restart = 1` (`:132`) and the inline `allocate` + `hdf5_restore` (`:143-144`).
  - `test_inventory.py` parses every family `input.py` (Python `ast`) and fails on an assignment to `restart` or a call
    to `hdf5_restore` or `exmain`.
  - The file is executed verbatim in every child and never split. The parent imports only.
- **Time-step configuration.** With `dtreal=1e20`, `add_timestep` is skipped (`bbb/pandf.m:737-741`). Inputs that act
  only when `dtreal` is finite (for example `fdt*xy` and `cfqydt`, `bbb/pandf_potencur.m:217-222,286`) are therefore
  INERT in the steady configuration. Each family has a second, **`timestep` configuration** (step 6), whose default is
  stored as its own reference. `overrides.toml` can run any variant in that configuration. The initial list is
  `fdt*xy` and `cfqydt`. `dtreal`, `ylodt` and `dtuse` are not `+input` variables (`bbb/bbb.v:2887,2891,2905`).
- **Process model.** Children come from a `multiprocessing` **forkserver** that preloads `uedge` and `numpy`.
  - The forkserver is a single-threaded process, so this stays safe inside an xdist worker (which has an execnet thread)
    and with BLAS thread pools.
  - It is started with `HOME` and its working directory set to an empty temporary directory, so `import uedge` cannot
    execute a `.uedgerc.py` (`src/uedge/__init__.py:59-67`).
  - Each child asserts that `uedge` is already in `sys.modules`, because a failed preload is otherwise silently ignored,
    and that no `.uedgerc.py` exists in its family directory.
  - Where forkserver is unavailable, the harness spawns fresh processes with the same environment, **including the
    same `HOME`/working-directory isolation at import time**. That is slower, with the same semantics.
    `UEDGE_BANNER=0` keeps each import free of network calls.
  - CI builds are `--serial`.

### Facts the design relies on (checked during planning)
- `pandf` is Python-callable (`bbb/bbb.v:3377`). There is no `pandf1` in v9.
- With a large `ftol`, `exmain` performs one function evaluation and stops (`svr/nksol.m:1005-1015`, `nkstp0` at
  `:1364-1399`). `uedge` then calls `convsr_vo1/vo2/aux` (`bbb/odesolve.m:416-418`). The explicit `pandf` call in step 8
  is what fills the flux and residual intermediates.
- `issfon=0` sets `sfscal=1` (`bbb/odesolve.m:289-296`). Raw `yldot` does not depend on `sfscal`, whereas `fnrm` does.
- `yl(neq+1)` and `yl(neq+2)` are control flags (`bbb/oderhs.m:1716,1726,1931`). The flag's sign selects physics:
  `ishosor` (`bbb/pandf_plasma_continuity.m:714`), `ismcnon` (`:39-62`) and `add_timestep`.
- **Known history caveat.** The old suite says "fnrm still changes after 1 exmain, but not after 2"
  (`upstream/pytests:templates/tests/uedge_tst_template.py:38`, `MakeTests.py:31`). The planning check on the slab case
  (repeated calls bit-identical, A→B→A reproducing A) covers one family only. Phase 1 characterizes every family and
  fixes `W` and `P`. Every child starts from a fresh, import-only process, so history can only act *within* a child:
  through the warm-up, the locality check's repeated calls, and optional child reuse. Child reuse is allowed only for
  families that pass.
- The `upstream/pytests` templates hold the states from before the ±1 % perturbation. `perturb_solution` is applied
  only to the generated copies (`uedge_tst_template.py:203-204`). They are 32–168 KB each.

### Key patterns
- **Golden-master testing** of `yldot`. References are generated from a named commit in a separate build, not
  maintained by hand.
- **OFAT on the family's own configuration.** Each variant changes one input away from the family's value. The class is
  asserted, so a refactor that stops reading an input is caught.
- **Storage interface with two implementations.** Full vectors give exact localization. Sketches stay constant in size.
  The large family uses sketches and the small families use full vectors (decision 12). A small family over its cap
  is escalated to the epic owner, never switched automatically (§7.3).
- **One binary file plus one text manifest per family.** Each family has a single tracked binary. The manifest is the
  reviewable diff, and the reference guard reads it.
- **Base states stored as data, not regenerated,** so a change in numpy's random number generator cannot move
  references.

## 7. Tools/Features

### 7.1 Families and base states (`tools/make_base_state.py`)
- **Input:** a converged state.
  - Small families: the template `solution.h5`. Phase 1 checks convergence on the reference build: the scaled `fnrm`
    (`issfon=1`) must be ≤ the case's `ftol`.
  - The round-5 review measured this on an installed v9 beta build. `d_only`, `ortho` and `slab` are converged. `d_mols`
    (scaled fnrm ≈ 2.2) and `d_c` (≈ 9e-5) are **not**.
  - **Fallback for any family that fails:** reconverge it **on the same grid** with the reference commit (time-stepping
    from the template state, `rundt`). Store the result as `converged_state.h5`, and record the commit and final `fnrm`
    in `family.toml`. The epic owner confirms this in Phase 1. It is consistent with decisions 3 and 11, because no
    grid changes.
  - Large family: the epic owner's save file, grid and input.
- **Perturbation,** seeded and bounded:
  - multiplicative log-normal `x·exp(σ·N(0,1))` on `nis, tes, tis, ngs, tgs`;
  - additive noise on `ups`, scaled by the local sound speed (random sign allowed where `|up|` is small);
  - `phis` changed by an additive `σ·Te`.
  - **σ is a few percent** (decided). Phase 1 fixes the exact value, for example 0.02–0.05, so that every equation
    block of `yldot` sits clearly above round-off.
- **Guards:**
  - densities and temperatures stay above the code floors;
  - no NaN or Inf;
  - `log(ng)` stays valid when `ineudif=3`;
  - no more cells at floors or limiters than in the converged state.
- **Output:** `base_state.h5`, in the `uedge.hdf5.hdf5_restore` format (`src/uedge/hdf5.py:30-35`, including
  `tipers`), plus `converged_state.h5` (the unperturbed physical arrays, same format).
- **Rationale** (decided in planning):
  - Convergence is not needed for an old-vs-new comparison.
  - A converged state keeps the evaluation in realistic regimes (sheath, recombination, rate-table ranges, no extra
    limiter activity).
  - At an exactly converged state `yldot ≈ 0`, so comparisons are dominated by cancellation noise.
- **Why the family mix:**
  - **8x4 snull grids** (`ixpt1=2, ixpt2=6, iysptrx=1`) merge cell classes:
    - the single core/PF row is next to both the core boundary and the separatrix;
    - the inner leg has only a plate-adjacent cell and a cut-adjacent cell.
    - The local window `ix−2…ix+1, iy−2…iy+2` (`xlinc=2, xrinc=1, yinc=2`, `bbb/bbb.v:1111-1113`) is clipped by the
      domain for almost every cell.
  - **The 32x17 slab** exercises unclipped interior windows, but has no X-point.
  - **The 16x8 `d_c`** (`ixpt1=4, ixpt2=12, iysptrx=4`) partly separates the classes.
  - **The 100x50 large family** separates them fully on a realistic geometry.

### 7.2 Input inventory and variant generator (`harness/inputs.py`, `variants.py`)
- **Inventory.**
  - The parser reads every `*/*.v` file for `+input` and `+maybeinput` tags. Tags after a `#` are ignored.
  - At planning time there are 971 tag lines (`bbb` 842 + 108, `com` 19, `aph` 1, `api` 1). Three of them are inside
    comments (`bbb/bbb.v:558,2073,2076`), which leaves **968 effective**.
  - Most are real or integer scalars and arrays. Seven are character or filename variables (`geometry`, `mcfilename`,
    `coronalimpfname`, `svrpkg`, `petscoptfile`, `petscopts`, `GridFileName`).
  - Keys are **package-qualified** (`bbb.isphion`, `com.iprint`).
- **Additions.** `overrides.toml` may also **add** untagged variables that affect `yldot` or locality. The initial list
  is `bbb.isflxvar`, `bbb.isrscalf` (`bbb/bbb.v:1298,1301`), `bbb.xlinc`, `bbb.xrinc`, `bbb.yinc` and
  `bbb.isjaccorall` (`bbb/bbb.v:1111-1114`). This extends decision 8 beyond the tags, so the epic owner confirms the
  list in Phase 2.
- **Harness-pinned variables.** Every tagged variable that the harness pins is in the initial EXCLUDED list with reason
  "pinned by harness": `bbb.restart` (`bbb/bbb.v:3083`), plus any of `issfon`, `ftol` and `iprint` that carry a tag.
  `test_inventory.py` asserts that every pinned tagged variable is EXCLUDED.
- **Base value `d`** is the family's **live value at the moment the variant is applied**, read from the Forthon
  variable, not the `.v` default. For scalars and static arrays that moment is after `input.py` (PRE). For dynamic
  arrays it is after `input.py` plus `allocate` plus restore (POST; §6). Default value rules, all overridable:

  | Type | Variant value |
  |---|---|
  | integer, d ∈ {0,1} | 1 − d |
  | integer, other d | d + 1 (override expected; index-like inputs such as `jxsori`/`jxsoro`, `bbb/bbb.v:644,646`, need one) |
  | `meth*` | each allowed value ≠ d: `methn` 22/33; `methu/e/i/p` 22/33/44/55; `methg` also 66/77 (`bbb/bbb.v:33-41`) |
  | real, d ≠ 0 | d·1.1 |
  | real, d = 0 | 1.0 (typical `cf*` toggle) |
  | array | rule applied to the whole array |
  | character / filename | EXCLUDED unless overridden |
  | layout-changing (`nisp`, `ngsp`, `nhsp`, `nxcore`, `ny*`, …) | EXCLUDED (new family) |

- **Applied value recorded.** The manifest stores the exact value applied (and `d`). Tests **replay** the recorded value
  rather than recomputing it from the rules. A change to a `.v` default or to a rule therefore cannot silently change
  what a reference means.
- **Timing.** PRE for scalars and static arrays, POST for every dynamic array (§6 phase rule). `overrides.toml` can
  force the phase, and can select the `timestep` configuration for a variant.
- **Classification,** made per family when references are generated. Each SENSITIVE variant is generated **twice** in
  separate processes, and any difference makes it INVALID ("nondeterministic") and files a bug.

  | Class | Definition | Stored | Asserted at test time |
  |---|---|---|---|
  | SENSITIVE | some entry differs from the default by more than M_cls·tol (classification margin M_cls = 100) | variant data | matches its reference |
  | INERT | bitwise equal to the default on the generating build | nothing | equals the default within tol |
  | MARGINAL | 0 < difference ≤ M_cls·tol | nothing | treated as EXCLUDED until an override gives a larger value |
  | INVALID | setup raises (`xerrab`/exception), process crashes, timeout, `neq` changes, non-finite `yldot`, bounds-check error in the audit build, or nondeterministic | message | still invalid (any change is reported) |
  | EXCLUDED | not run | reason | – |

### 7.3 Reference storage (`harness/store.py`)
- **FullVectorStore** (small families):
  - the default `yldot` (float64);
  - the index maps;
  - the diagnostic intermediates (`res*`, the `Comflo` fluxes, the main sources);
  - each SENSITIVE variant as the entries that differ from the default (int32 index + float64 value). Entries not
    stored must equal the default.
- **SketchStore** (large family only; decision 12):
  - the full default `yldot` and the `res*` arrays;
  - for each SENSITIVE variant and each block (equation × species × region), k = 8 projections onto fixed seeded
    **Rademacher (±1)** vectors, plus the L2 norm, the largest |entry| and its location.
  - The signs are taken from the raw bits of numpy's `PCG64` bit generator (`bit_generator.random_raw`), whose stream
    numpy keeps stable across versions. `Generator.normal` is not stream-stable, so it is not used. Projections are
    computed in float64, summed in a fixed order.
  - Regions: inner leg, core, outer leg, SOL, private flux, and boundary/guard rows.
  - A change above tolerance escapes only if it is orthogonal to all k vectors.
  - Limitation: a change confined to cells whose entries are small next to their block can be diluted. Per-region blocks
    reduce this.
- **Files:** one HDF5 file per family, plus `<family>.manifest.json`.
  - Per variable, the manifest holds:
    - class, reason, applied value, `d`, phase and configuration;
    - the SHA-256 of the stored data and the per-block L2 norms.
  - Per family, it also holds **guarded SHA-256s** of:
    - the default `yldot` for the steady and `timestep` configurations;
    - every locality pattern.
  - It holds an **unguarded** SHA of the diagnostics.
  - It records provenance: commit, compiler version, flags, runner image, numpy, date.
- **Estimated sizes.** Assumptions: about 968 variants, 40 % SENSITIVE, each touching 30 % of the entries. Phase 2
  re-checks them against the caps.

  | Family | numvar (est.) | `neq` (est.) | Reference file | Cap |
  |---|---|---|---|---|
  | `d_only`, `ortho` (8x4) | ~8 | ~500 | ~0.7 MB each | 2 MB |
  | `d_mols` (8x4) | ~10 | ~600 | ~0.9 MB | 2 MB |
  | `d_c` (16x8) | ~21 | ~3,800 | ~5.5 MB | 7 MB |
  | `slab_phi` (32x17) | 7 | 4,522 (measured in planning) | ~6.5 MB | 9 MB |
  | `large_dd2c` (100x50) | ~22 | ~117,000 | ~3 MB sketches + ~2 MB default/`res*` | 6 MB |

  Other contributions:
  - the large family's state and grid, about 6–7 MB;
  - the rate files, about 0.5 MB;
  - the small states and grids, about 0.8 MB;
  - the locality patterns, sparse and estimated at under 0.5 MB in total.

  **Working-tree total ≈ 28 MB, budget ≤ 30 MB.** If a small family exceeds its cap, the epic owner decides: raise
  the cap, EXCLUDE low-value variants, or move that family to sketches. The move is not automatic, because full
  vectors for small families are decision 12.
- **History growth.** Every regeneration of a family's file adds a whole new blob to git history (decision 12 accepts
  this).
  - `check_reference_change.py --history` reports the cumulative size of blobs under `tests/references/` across
    history.
  - At 150 MB, the epic owner is asked whether to move to LFS or release assets.

### 7.4 Comparison and localization (`harness/compare.py`)
- **Full vectors:** `|new − ref| ≤ atol_eq + rtol_eq·|ref|`, with `atol_eq = rtol_eq·max|ref_eq|` per equation block.
- **Sketches:** `|⟨new−ref, r_j⟩| ≤ rtol_eq·⟨|ref|,|r_j|⟩ + atol_block`.
- **Tolerances.** Variants inherit the per-equation tolerances of the default. Phase 1 confirms this on a sample of at
  least 20 variants per family.
- **On failure:**
  - full vectors: map the index via `igyl`/`idx*` to (equation, species, ix, iy). Report the worst entries and the
    failing count per equation, and, from diagnostics only, the first intermediate that differs in `pandf` call order;
  - sketches: report equation, species and region, and the stored versus new location of the largest entry. The cell
    is found with `make_references.py --from-commit <manifest commit> --full --only <variant> --family <f>`.

### 7.5 Locality check (`harness/locality.py`)
The check follows `jac_calc` (`bbb/oderhs.m:1012-1240`) and is an **old-vs-new comparison of the locality pattern**.
It does not assert perfect locality.

1. Set `yl[neq] = +1` (the Jacobian flag, as `jac_calc` does for both calls). Run a full evaluation at the base `y0`,
   giving `f00`.
2. For each column `iv`:
   1. **Reset the work vector to `f00`**, as `jac_calc` does for every column (`bbb/oderhs.m:1142`).
   2. Perturb `yl[iv]` by `dyl = δ_loc·(|y|+dylconst/suscal)`. This is `jac_calc`'s formula, with a harness-chosen
      `δ_loc` (see calibration below).
   3. Call `pandf(igyl(iv,1), igyl(iv,2), …)` locally into the work vector. Rows outside the window keep `f00`.
   4. Run a full evaluation at the perturbed `yl` with the same flag.
   5. Restore `yl[iv]`, then call `pandf(xc,yc)` again at the restored `yl`, as `jac_calc` does
      (`bbb/oderhs.m:1216`). Repeat the full evaluation at `y0`, so that no stale intermediates carry over. Each column
      costs **2 local + 2 full** evaluations.
   6. Record the **mismatch** `m_r = |Δ_full,r − Δ_local,r|` for each row `r`, normalized by
      `atol_eq + rtol_eq·|Δ_full,r|`.

**Calibration (Phase 3).** Weak couplings must be visible above the margin band. The worry: with `jac_calc`'s
`del = 1e-8` and a cross-platform `rtol` near 1e-9, a dropped weak coupling scores only about 3, inside the unasserted
band.
- Phase 3 therefore chooses `δ_loc` (for example 1e-4–1e-3) and the locality band `M_loc` (separate from the
  classification margin `M_cls`, §7.2).
- Two committed **range mutations** must both score above `M_loc`:
  - the `initialize_ranges` mutation;
  - a second one that removes a single weak coupling *from the evaluation window*, for example one neighbour row in a
    point-wise source range.

  Physics mutations are invisible to this check by construction, and are caught by the `yldot` tests.
- This is required on `slab_phi`, `d_c` and `large_dd2c`, which have unclipped windows. On the 8x4 families it is
  demonstrated where a suitable column exists, and recorded as not demonstrable otherwise.
- The chosen values are recorded in `family.toml`, which is guarded (§7.6).

**Pattern with a margin band.**
- The stored pattern `P` is the set of rows with normalized mismatch **> M_loc** (initially 100, calibrated in
  Phase 3), with their magnitudes.
- At test time, a row in `P` must still exceed 1 and match its magnitude within tolerance. A row outside `P` must stay
  **≤ M_loc**.
- Rows between 1 and `M_loc` are recorded but not asserted, so a row near a threshold cannot flip between
  platforms.

**Reference.** The pattern for each family and configuration is stored in the family's reference file, with a guarded
SHA in the manifest. The test asserts that it is **unchanged** in this sense. Mismatches that are differences by design
are expected to appear in the pattern, and are named in the reference:

- `ExtendedJacPhi` with `isphion*isnewpot=1`, and `isextr*` boundary conditions, which widen the `jac_calc` band
  without `initialize_ranges` (`bbb/oderhs.m:1125-1138`);
- cuts, core and `isjaccorall` windows (`bbb/pandf.m:53-55,114-155`).

A too-narrow window, or a stale cell from a refactor, adds rows to the pattern and fails the test.

**Columns and tiers:**
- PR tier: every column of the small families in the default configuration.
- Nightly tier, large family: every variable at all cut, X-point, plate, separatrix, corner and boundary cells, plus a
  seeded sample of about 300 interior columns.
- Nightly tier, all families: the `meth*` variants. On the large family these use the special-cell columns only.
- Nightly tier, small families: the **locality inputs**. These are the override additions `xlinc`, `xrinc`, `yinc`
  and `isjaccorall`, which do not change the full `yldot` but do change the windows. They are varied one at a time
  through the locality check rather than the `yldot` sweep.

The planning check on slab (default, non-flag-gated physics) found bit-identical columns. That is evidence for the
protocol, not a guarantee for other families.

### 7.6 Reference generator and guard (`tools/make_references.py`, `check_reference_change.py`)
- **`--from-commit <sha>`:**
  1. creates a temporary worktree and venv;
  2. builds that commit `--serial` with the CI flags;
  3. runs classification (twice for SENSITIVE), the locality patterns, and, on a full run, the `--checkbounds` audit;
  4. rewrites `references/<family>.h5` and the manifest.
- **Committed references** are produced by the `regenerate-references.yml` workflow on the pinned runner image, with the
  gfortran version pinned. Local runs are previews.
- **Other options:**
  - `--only <var…>` regenerates the selected variants, including their `--checkbounds` audit and double generation.
    Every other entry's stored data stays identical, which the SHA in the manifest verifies.
  - `--full` writes full vectors for a sketch family to a temporary file, for localization.
- **Refactor maintenance:**
  - `--prune` removes manifest entries for variables no longer in the inventory.
  - `--rename old=new` re-keys an entry. It requires the same applied value, and the re-run must reproduce the stored
    data.
- **The guard (`check_reference_change.py`, in CI)** compares the manifests of the PR base and head. It runs on
  `pull_request_target` events (`opened`, `synchronize`, `reopened`, `edited`), so adding the declaration later re-runs it.
  - The PR description is passed to the script through an environment variable (`PR_BODY:
    ${{ github.event.pull_request.body }}`), never interpolated into a shell command.
  - On `push` and `schedule` events the guard is skipped. Changes reach `v9-develop` only through PRs.
  - Allowed without a declaration:
    - **additions**: new keys, such as the variant for a new default-off switch, with every existing guarded SHA
      unchanged;
    - **prunes** of entries that were INERT, MARGINAL, INVALID or EXCLUDED in every family;
    - **renames** with identical SHA;
    - **diagnostics-only** changes: only the unguarded diagnostics SHA differs.
  - Anything else requires the line `Default results: changed` in the PR description, followed by the changed
    variants. Anything else means: a changed or removed SENSITIVE entry, a changed default or `timestep` vector, or a
    changed locality pattern. The exact keyword is added to the CLAUDE.md hard rule by the AI-layer "adopt" PR.
  - **Test criteria are guarded too.** The guarded set is **everything under `tests/`**, plus the workflow files
    `build-test-wheel.yml`, `nightly-tests.yml`, `reference-guard.yml` and `regenerate-references.yml`. Not guarded:
    - new reference entries that count as *additions*;
    - new files under `tests/mutations/`.

    Rules:
    - Any change to the guarded set requires a separate line `Test criteria: changed`, with a justification.
    - These count as a **loosening**. They additionally require a line `Test criteria: loosened`, with a
      justification, **and** approval from a CODEOWNER of `tests/**` (the epic owner), so a criterion can never be
      relaxed to make a moved `yldot` pass silently. `Default results: changed` keeps its CLAUDE.md meaning: defaults
      moved. It is not used for test-criteria changes.
      - a larger value in `tolerances.toml` (rtol/atol, safety factor, floor), or a larger `M_cls` or `M_loc`;
      - a change or removal of an existing `overrides.toml` entry;
      - **by default, any change** to the harness code (`tests/harness/**`, `conftest.py`, `test_*.py`), to the guard
        script, or to non-monotone parameters (`W`/`P`, `δ_loc`, sketch `k`/regions/seed, timeouts, `Δt`). Whether
        these are tighter or looser cannot be decided mechanically.
    - These need only `Test criteria: changed`:
      - a smaller tolerance or margin;
      - a new override entry;
      - removing the override of a variable that the same PR prunes from the inventory (story 10).
    - `test_inventory.py` parses every Python file under `tests/` with `ast`. It fails on any decorator or call that
      resolves to `pytest.mark.skip`, `pytest.mark.skipif`, `pytest.mark.xfail`, `pytest.skip` or `pytest.xfail`.
      Because the check works on syntax nodes, its own pattern strings do not match. Variants are excluded only
      through manifest classes.
    - **The guard cannot be changed by the PR it judges.**
      - `reference-guard.yml` triggers on **`pull_request_target`** (opened, synchronize, reopened, edited), so GitHub
        runs the base branch's copy of the workflow and of `check_reference_change.py`.
      - It fetches the PR head **as data only** (`git fetch origin pull/<n>/head`) and diffs and parses the manifests and
        TOML files. It never executes PR code.
      - It runs with `permissions: contents: read, pull-requests: read`.
      - Changes to the guard itself therefore take effect only after merge, and count as a loosening.
    - **Branch protection,** set up by the epic owner as repository admin in Phase 3:
      - `reference-guard.yml` is a **required status check** on `v9-develop`;
      - a `CODEOWNERS` entry for `tests/**` and `.github/workflows/**` requires the epic owner's review.
  - **Integrity at test time.** Before comparing, each test recomputes the SHA-256 of the datasets it reads from
    `references/<family>.h5`, and fails if any differs from the manifest. A changed `.h5` with an unchanged manifest
    therefore fails.
  - **Workflow.** The guard runs in its **own workflow**, `reference-guard.yml` (`pull_request_target`: opened,
    synchronize, reopened, edited). Editing the PR description then re-runs only the guard. `build-test-wheel.yml` keeps its existing
    triggers, and no test job is skipped on `edited`.

### 7.7 Round-off and history measurement (`tools/measure_roundoff.py`, `measure_history.py`)
**Round-off.** Per family and per equation, it measures the maximum relative and absolute spread of `yldot` between:

- the same build run twice in separate processes;
- `-O0` without FPE traps against the default `-O3`. This needs a new opt-in, results-neutral build option. `--debug`
  (`-Og`, `-ffpe-trap=invalid,overflow,underflow`, `-finit-real=snan`, `setup.py:84-91`) is also tried. If it traps
  (for example on underflow in rates), the trap location is recorded as a finding, not as a spread;
- serial against OpenMP with 1 and N threads, via the `ffun` path with `ppp.OMPParallelPandf1=1` (RHS only);
- macOS (developer machines) against Linux (the pinned CI image).

**OpenMP RHS + Jacobian check** (`tools/omp_check.py`, OpenMP build, local).
- This is the harness replacement for today's `validate` §4 (`.claude/skills/validate/SKILL.md:70-79`), which needs a
  case that loads a state. The new family `input.py` files never do.
- Steps:
  1. The tool runs in its own process with **`OMP_NUM_THREADS=N` (default 4)**. It does not use the harness's
     `OMP_NUM_THREADS=1` pinning, because `ppp` clamps `Nthreads` to `OMP_GET_MAX_THREADS()`
     (`ppp/omp_parallel.F90:296-303`).
  2. A `state.py` helper loads a family: `input.py`, then `allocate`, then restore of the **perturbed
     `base_state.h5`**, using the case's normal `ftol` (not `1e50`). Starting off-converged guarantees that `nksol`
     iterates and builds a Jacobian. From a converged state, its `nkstp0` test stops at iteration 0, before
     `pset`/`jac_calc` (`svr/nksol.m:1005-1015,1394-1398`).
  3. Set `ppp.OMPParallelPandf1=1`, `ppp.OMPParallelJac=1`, `ppp.Nthreads=N`, `ppp.CheckPandf1=1` and
     `ppp.CheckJac=1`, then run `bbb.exmain()`.
- **It fails unless** all three hold:
  - the effective `ppp.Nthreads` after the run is > 1;
  - the `CheckJac` comparison actually ran: its banner (`ppp/parallel.F90:112`) appears in the captured output, or an
    equivalent counter is set;
  - `CheckPandf1` ran.
- It reports the serial-vs-parallel RHS **and** Jacobian comparison as today, with the `CheckPandf1` / `CheckJac`
  output verbatim.
- `measure_roundoff.py`'s "OpenMP with N threads" row uses the same rule: its own process with `OMP_NUM_THREADS=N`,
  and a recorded effective `Nthreads` > 1.
- It runs on `d_c` by default, or on any family with `--family`. It keeps the race check for missing `+threadprivate`
  in the Jacobian (`.claude/context/openmp-jacobian.md`).

**History** (`measure_history.py`). For every family it compares:

- `exmain` ×1 against ×2;
- the first `pandf` call against the second;
- A→B→A sequences.

It sets `W` and `P`, decides whether child reuse is allowed, and confirms that the locality protocol's repeated calls
reproduce.

**Findings.** Any nonzero same-build or within-process difference is filed as a defect (uninitialized memory or
ordering), not absorbed into tolerances. The epic owner's observed "randomness", and the old suite's "changes after 1
exmain" note, must be explained.

**Output.** `tolerances.toml`, with `rtol_eq` = a safety factor (100) × the measured spread, floored at 1e-14, together
with the raw measurements.

### 7.8 Mutation set (`tests/mutations/`, `tools/run_mutations.py`)
The set has **25 committed single-line patches**: a sign flip, a factor of 2 and a dropped term in each of plasma
continuity, momentum, electron energy, ion energy, gas continuity, gas energy and potential (21), plus four more:

- an off-by-one neighbour (`ix-1` in place of `ixm1(ix,iy)`) at an X-point cut, which the large family must catch;
- a wrong `cf*` multiplier;
- two **range mutations** that the locality check must catch (§7.5):
  - a wrong loop bound in `initialize_ranges`;
  - a single weak coupling removed from the evaluation window.

Each patch names the test expected to catch it. The runner applies them one at a time in a scratch worktree. It is run
at the end of every phase, not on every PR.

  - About 35–45 CPU-min for large locality.
  - About 40–80 CPU-min for small-family `meth*` and locality-input checks.
  - Sharded across about 6 jobs on 4 vCPU. **Target: ≤ 60 min wall.**
- **If the budgets are exceeded:**
  - reduce the per-child setup (reuse a child for consecutive INERT-candidate variants, but only on families where the
    history check passes);
  - perturb locality columns in coloured groups whose windows do not overlap;
  - move the slab locality check to nightly.
- Budgets are checked in Phase 2 (sweep) and again in Phase 3 (with locality).

### 7.10 Coverage report (`tools/coverage.sh`, Phase 4)
- Builds `--serial` with `--coverage -O0`, through an opt-in build option.
- Runs the new suite, and once the old `upstream/pytests` suite.
- Reports line and branch coverage of `bbb/pandf*.F` with `gcov`/`gcovr`.
- Coverage maps to generated `.F` lines. An approximate `.F`→`.m` map is built by matching unique source lines, because
  `MoveDecs` reorders declarations (`setup.py:217`).

## 14. Risks & Mitigations

| # | Risk | Mitigation |
|---|---|---|
| 1 | **Nondeterminism and history dependence** (the observed "randomness"; "fnrm changes after 1 exmain"; `-O3` vs `-O0`; OpenMP order; macOS vs Linux). Tolerances end up so loose that real changes pass, or so tight that CI flakes. | Phase 1 measures history and round-off on every family before any reference is committed. Same-build differences are treated as bugs. `W`/`P` are fixed per family. References are generated on the pinned CI image. Tolerances are set per equation, with provenance. |
| 2 | **OFAT misses interaction bugs.** | Six families already switch on the main parent models: molecules, impurities, potential/drifts, orthogonal grid, large geometry. The coverage report exposes unreached branches. Overrides (including additions) close gaps. Pairwise testing is future work. INERT is never treated as proof that an option is dead. |
| 3 | **Unsafe variants:** crashes, hangs, out-of-bounds reads producing platform-dependent "SENSITIVE" references. | Forked children with timeouts. Crash, timeout and nondeterminism are INVALID classes. The `--checkbounds` audit. Double generation. Overrides for index-like inputs. |
| 4 | **Runtime or data budget exceeded** (about 5,800 variant evaluations across six families, plus locality). | The §7.9 cost model, measured in Phase 1. A forkserver preloads the import once. Build once, then sharded tests. Two tiers. Per-family caps escalated to the epic owner. Coloured locality columns. Child reuse only on history-clean families. |
| 5 | **Perturbation too small or too large.** | A converged background with a few-percent perturbation. Phase 1 checks every block against round-off, and checks floors and limiters against the converged state. |
| 6 | **Sketches dilute small local changes** in the large family. | Per-region blocks. The default is a full vector. The special-cell mutations verify sensitivity. The small families carry the per-entry checks. |
| 7 | **Reference churn hides real changes** during the code reduction. | References only come from the CI regeneration workflow. `check_reference_change.py` in CI only accepts declared changes or a refactor-safe prune/rename. The `code-review` skill flags manifest diffs. |
| 8 | **The locality pattern is noisy** (by-design non-local couplings, flag-gated physics), so the check is either brittle or meaningless. | The protocol mirrors `jac_calc` exactly, including the flag and the restore. The pattern is stored and compared rather than required to be empty. Every nonempty pattern is attributed in Phase 3. |

## 15. Appendix

### Binding decisions (planning conversation, 2026-10-14)
1. **Purpose.** The suite detects accidental changes during refactoring by comparing old against new. Physics
   correctness is out of scope.
2. **Linear coverage.** Each part or option is tested, not permutations ("n tests, not n²").
3. **Converged starting points.** Every tested configuration starts from a converged case.
4. **Later epic.** MMS and conservation checks go in a new, separate epic.
5. **Design.** Golden-master `yldot` references with OFAT variants (A), a locality check (D), references generated by
   building a named commit (B), and gcov coverage as a later phase (E).
6. **Location.** The suite lives **in this repo**. `upstream/pytests` is **retired** once the new suite is in place.
7. **Data.** Base states may be committed. External fetching is not needed.
8. **Variants.** **All `+input`/`+maybeinput` variables in the `.v` files**, not the existing `templates/` snippets.
   (§7.2 proposes optional *additions* of untagged variables, to be confirmed by the epic owner.)
9. **Tolerances.** They are **measured**, including the `-O0`/`-O3` round-off spread, not fixed in advance.
10. **Base state.** **A converged state plus a numerical perturbation of a few percent.** A fully non-converged noisy
    state was considered and not chosen.
11. **Families.** **Small cases from the existing `upstream/pytests` templates** (slab, molecular, D+C, and so on),
    **plus large (~100x50) converged cases** from the epic owner. Fine cases are not coarsened.
12. **Reference storage.** **Full vectors for small families, projection sketches for large ones.** **One reference
    file per family**, with a text manifest.
13. **CI.** Two tiers are acceptable: small families on every PR, the large-family sweep nightly or on PRs that touch
    Fortran.

### Assumptions (not explicitly decided)
- The data budget (≤ 30 MB working tree, history review at 150 MB) and the runtime budgets (PR ≤ 20 min, nightly
  ≤ 60 min) are proposed targets.
- There is one large family (D+D2+C), supplied by the epic owner in Phase 1 with its grid and inputs.
- The `d_only`, `ortho` and `slab` templates are converged. `d_mols` and `d_c` are not, according to the round-5
  measurement on a v9 beta build. Phase 1 re-checks on the reference build, and reconverges any failures on the same
  grid (§7.1).
- `upstream/pytests` belongs to LLNL. "Retire" means stop using it here, not delete the upstream branch.
- The sizes, numvar and costs in §7 are estimates, measured in Phases 1–2. Only the slab's `neq` (4,522) and setup time
  were measured in planning, on a pre-installed v9 build.
