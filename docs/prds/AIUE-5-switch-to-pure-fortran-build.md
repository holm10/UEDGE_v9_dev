## 1. Executive Summary

UEDGE's physics is written in MPPL, a fixed-form Fortran dialect with macro extensions. 52 `*.m` files (~94k lines; 50 of
them compiled) are converted into `.F` on every build by `mppl2f90()` in `setup.py` (`setup.py:631-673`). The converter is
mostly **plain substring replacement** over whole lines, comments included (`#`→`!`, `float`→`real`, `break`→`exit`,
`while (`→`do while (`, `Use(X)`→`use X`), plus stateful line rewriters (`MoveDecs`, `Elseifthen`) and environment switches
(`Omp`, `Petsc`, `Nopdb`). So the code that is compiled is never the code that is checked in, diagnostics point at
generated files, and standard tools don't understand the sources. The legacy BASIS build duplicates the file lists by hand.

This epic replaces every compiled `.m` with a committed **free-form `.F90`**, the form already used by the hand-written OpenMP
code in `ppp/`. The conversion is mechanical and runs in two stages:
1. The existing converter runs **unmodified** for the serial and the OpenMP build. The two fixed-form outputs are merged with `#ifdef _OPENMP`
   guards, and a comment pass restores comment text the converter altered. This is the **fixed-form reference**.
2. A fixed→free converter turns the reference into `.F90`: continuation `&`, `!` comment markers, labels, and character-context continuation
   with fixed-form padding preserved.

Three gates prove the result:
- **same parsed program:** gfortran's parse-tree dump of the `.F90` equals that of the reference, in both builds;
- **same numbers:** exact residuals across the regression suites, a grid-generation case and an OpenMP case;
- **no comment information lost.**

PETSc, PACT and BASIS are removed. Forthon and the `.v` files don't change, so the Python API is unchanged.

**MVP goal:** `pip install .` builds UEDGE from committed free-form `.F90` sources, with no MPPL conversion step and no BASIS
artefacts. The compiled program and every regression number are unchanged, and no comment information is lost.

## 2. Mission

Make UEDGE's source code the code that runs: standard, modern-form Fortran that humans and agents can read, edit, grep and
debug directly, without losing a line of the documentation in it.

**Core principles**
1. **Same program, same numbers.** This is a refactor. Any parse-tree or residual difference is a defect in the migration.
2. **Nothing said in a comment is lost.** Comments may move or change marker, but their information survives, and a machine
   check proves it.
3. **Mechanical and verifiable.** The sources come from tools and machine checks, never hand-porting. Every checker has
   negative controls that prove it can fail.
4. **One build system, one source form** for converted code. BASIS goes, and its unique test coverage is replaced first.
5. **No user-visible change, and the docs stay true.** The AI layer and docs change in the same PR as the code they describe.

## 5. User Stories

1. **As a core developer, I want compiler errors to point at the file and line I edit**, in a format my editor understands.
   *Example:* a type error reports `bbb/pandf_plasma_energy.F90:431`, which is the tracked line, and fortls resolves `use Compla`.
2. **As a physicist reading the code, I want every explanatory comment, citation and banner to survive.**
   *Example:* `c ... use float(nx) here, see Rognlien (1992)` becomes `! ... use float(nx) here, see Rognlien (1992)`.
3. **As a new contributor, I want to write standard free-form Fortran**, so that I don't need column rules or the MPPL dialect.
4. **As a v8 maintainer, I want a documented way to bring a v8 `.m` fix to v9.**
   *Example:* `tools/mppl_freeze.py backport <v8-commit>` emits the `.F90` patch.
5. **As an AI implementer agent, I want the committed source to be the compiled source**, so that review and grep reason about what runs.
6. **As an end user, I want my decks and save files to keep working with the same numbers.**
   *Example:* `hdf5_restore('save.h5')` + `exmain()` gives an identical `float.hex(fnrm)`.
7. **As a CI maintainer, I want one build pipeline without losing coverage**, including grid generation from an eqdsk.
8. **As a developer using OpenMP, I want the parallel RHS and Jacobian unchanged.**
   *Example:* the OpenMP case gives identical residuals at `Nthreads=4`.
9. **(Technical) As a reviewer, I want machine checks that can fail**, so that I can trust a ~94k-line diff.

## 6. Core Architecture & Patterns

### 6.1 Build pipeline: before → after

| Step | Today | After AIUE-5 |
|---|---|---|
| 1 | `pip install .` → `uedgeBuild.run` (`setup.py:697`) | same |
| 2 | `make clean` deletes every `*.F` | still deletes generated `<pkg>/*.F` (stale-file guard) and build products |
| 3 | `mppl2f90()` rewrites `*.m` → `*.F` (env switches `OMP`/`PETSC_DIR`/`PACT_DIR`) | **removed** |
| 4 | `Forthon3 --interfacefile <pkg>.v -f <pkg>/*.F` (fixed form, `-ffixed-line-length-132`) | `-f <pkg>/*.F90` (free form, selected by the suffix) |
| 5 | gfortran `-cpp -DFORTHON -fdefault-real-8 …` | same; serial or OpenMP only |
| 6 | BASIS build + Docker CI | **removed**; grid generation is tested in pytests |

### 6.2 Stage 1: fixed-form reference

Emitting `#ifdef` inside the MPPL rule chain corrupts declaration blocks (`MoveDecs` classifies lines by column, review P1-M1),
so stage 1 never changes the rule chain:

1. Per file, with **fresh rule state**, run the unmodified `M2F` rules with `OMP=FALSE` and `OMP=TRUE`, and with `PETSC_DIR`/`PACT_DIR` unset, as
   both of today's builds do.
2. Drop the `cpetsc`/`cunipetsc` lines, then merge with `diff -D _OPENMP serial.F omp.F`. Only `bbb/oderhs`, `bbb/odesetup` and `bbb/pandf`
   differ; both builds round-trip (verified in review round 2). The serial `c!omp` comment copies are not kept; their content is the
   `#ifdef _OPENMP` code.
3. Comment pass (§6.4).
4. The result is the **reference**. It is not committed; the tool regenerates it from the parent commit for every gate run.

### 6.3 Stage 2: fixed form → free form

The converter is chosen in Phase 0. The leading candidate is `findent` (review round 4 converted all 50 files with 4.3.6; 45 were identical
in the parse dump at once, and the dump caught the defects in the other 5), wrapped by the freeze tool to fix those defects. A converter built
on the freeze tool's own lexer is the alternative. Whichever is chosen is **version-pinned** (backports must reproduce it), applies the uniform
3-space indentation, and must pass the fixtures and gates. Requirements:

| Fixed-form construct | Free-form output |
|---|---|
| Continuation marker: any non-blank, non-zero character in column 6 (14 different characters occur; 1,700 lines are tab-formatted) | `&` at the end of the previous line, placed **before** any trailing `!` comment |
| Character context continued across lines (6 pairs, e.g. `aph/aphread.m:465-466`) | `&` at end and `&` at start of the next line, with the **fixed-form blank padding** (to column 132) written out, so the string value is unchanged |
| Statement label in columns 1-5 | leading label |
| Full-line comment `c`, `C`, `*`, `!`, column-1 `#` comment | `!` + identical text |
| Indented comment-only line (731: 715 `#`, 16 `!`) | full-line `!` comment + identical text |
| Comment whose text starts with `$` (e.g. 8 `c$$$` lines) | `! $$$…`, never `!$…`: a free-form `!$` line is an OpenMP sentinel. The inserted blank goes on the exception list |
| Fixed-form tokens split by blanks that free form would read differently (e.g. `external tick tock` at `bbb/oderhs.m:69` declares `ticktock`) | joined into the token fixed form meant (`external ticktock`); each case listed for a follow-up ticket |
| Inline `!` comment | unchanged |
| cpp directives (`#include`, `#ifdef _OPENMP`, `#endif`) | unchanged, column 1 |
| Blank-insensitive fixed-form code (`go to`, `end do`, `double precision`, any blanks inside tokens) | blanks normalised so each token is intact; checked by gate 1 |
| Hollerith (in `FORMAT`, e.g. `svr/svrut4.m:2189`, and anywhere else the Phase 0 scan finds) | kept if gfortran accepts it in free form with Forthon's flags (verified in Phase 0); otherwise converted to an equivalent character edit descriptor and listed |
| Code lines longer than 132 characters after conversion and cpp expansion | re-wrapped with `&` at token boundaries, never inside a string without `&…&`; comment lines are not wrapped |
| Continued `FORMAT` statements (56 in 10 files) | converted with `&`; the fixed-form padding blanks inside the format string are **not** written out (owner decision: insignificant whitespace); the FORMAT check proves the rest is identical |
| Comment lines between continuation lines | kept in place (allowed in free form) |

### 6.4 Comment information preservation

Comments don't affect the compiled program, so the comment pass and stage 2 can change their markers and positions without
touching gate 1. The MPPL converter changes comments in these ways (measured in round 1):

| Converter behaviour | Effect | Handling |
|---|---|---|
| `("#","!")` on the whole line | every extra `#` in a comment becomes `!` (382 comments, e.g. `c#####` banners in `api/sputt.m:6`) | restore the text |
| `float`/`dfloat`, ` break`, `while (`, `elseif` + `then` on the whole line | about 50 comments reworded | restore the text |
| `Use2use` strips `(`/`)` on the whole line | inline comments on `Use(...)` lines lose their parentheses | restore the text |
| `MoveDecs`/`Elseifthen` reordering | 84 comment lines in 17 files move | move back before their following-code anchor where it exists; otherwise keep in the routine and report |
| `do_i1` rules (`grd/grdcomp.m:4245,4259,4279,4284`) | `# exit do_i1` / `# do_i1` become code | **exception**: kept as code |
| `call ruthere` → comment (`bbb/pandf.m:552`, `bbb/oderhs.m:1078`) | code becomes a comment | **exception**: added, not lost |
| `c!omp` payloads | become `#ifdef _OPENMP` code | **exception**: kept as code |
| `c!nopdb` payloads | active stub code today | **exception**: plain code |
| `cpetsc`/`cunipetsc` lines incl. 15 PETSc-only comments | inactive PETSc code | **exception class (owner decision)**: removed with PETSc; listed by file and line |

**Requirements**
1. **No comment information is lost.** Every comment in a compiled `.m` (full-line `c`, `C`, `*`, `!`, column-1 `#`; indented comment-only
   lines; inline `#` or `!`)
   appears in the `.F90` with its text unchanged after the marker, or is on the exception list with the form its information now takes.
2. **Markers:** every marker becomes `!`. A full-line comment stays full-line. An inline comment stays inline on the same statement, or,
   on a continued statement, on the same physical line.
3. **Location:** within the same routine, immediately before its **following-code anchor** (the next code line in the `.m`) where possible.
   Every other placement is listed in the fidelity report.
4. **The exception list is exact** (file, line, `.m` text, `.F90` form). It is reviewed in the PR, and the check fails on any unlisted
   difference *and* on any listed exception that didn't occur.

**Lexer requirements** (shared by the comment pass and stage 2; the fidelity check deliberately uses its own extractor, §7.3). The lexer must handle:
- fixed-form columns and tab-format lines;
- strings continued across lines, with doubled quotes;
- Hollerith;
- `!` in code and inside strings;
- MPPL directives (`c!include`, `c!ifdef`, `c!else`, `c!endif`, `c!omp`, `c!nopdb`) and PETSc lines (`cpetsc*`, `cunipetsc`), which are not
  ordinary comments, while comments that merely start with `c!` (19 in `ncl/ncl_driver.m`) are;
- upper- and lower-case `c`;
- free-form `&` continuations on the output side.

## 7. Tools / Features

### 7.1 `tools/mppl_freeze.py`
- **Operations:** stage 1 (§6.2) → stage 2 (§6.3) → `<pkg>/<file>.F90` plus a per-file report: comments restored and relocated,
  exceptions, lines re-wrapped, Hollerith handling.
- **Modes:** `freeze <files>`, `reference <files>` (fixed-form reference only, for the gates), and `backport <v8-commit>` (§7.6).
- **Lifetime:** permanent while v8 is maintained. Its fixtures run in CI.

### 7.2 `tools/check_equivalence.py` (gate 1: same program)
- **Primary check, parse tree:** for both builds (serial; OpenMP with `-fopenmp`), run gfortran with the exact Forthon flags from the build log
  (`-cpp -DFORTHON -fdefault-real-8 -DFPSIZE -DISZ …`, plus `-ffixed-line-length-132` for the fixed-form side; the suffix selects the form). Use `-fsyntax-only -fdump-fortran-original`
  on two inputs: the fixed-form reference (regenerated from the **parent commit** of the freeze) and the committed `.F90`.
  - Source-location information is stripped.
  - Both sides compile against the **same** Forthon-generated module files, built from the PR's `.v`, so `.v` changes in the same PR
    (e.g. removing `petscoptfile`) don't show up as differences.
  - The dumps must be identical, including character constants, labels and the OpenMP branches.
  - Phase 0 proves that the dump is form-independent and complete enough. If it isn't, the check falls back to a form-aware token comparison
    with the same negative controls.
- **FORMAT check:** the parse dump does not print `FORMAT` statements (review round 4: changing `58h`→`57h` or `99i1`→`98i1` in
  `svr/svrut1` left the dump identical), so 256 FORMATs, including all 51 Hollerith descriptors, need their own check. It takes the compiled
  format strings from `-fdump-tree-original` (file/line strings normalised), independent of the converter's lexer. It compares them after
  removing whitespace (blanks **and tabs**) that is insignificant under the Fortran format rules (between descriptors, fixed-form padding,
  tab-formatted continuations such as `api/fmombal.m:693`) while keeping blanks inside character and Hollerith data. They must be identical.
  - **Unused FORMATs:** 13 FORMAT statements are never referenced (`svr/svrut4` 101-110, `bbb/oderhs` 77, `bbb/odesetup` 110, `flx/flxread` 1050;
    39 of the 51 Hollerith descriptors), so they never reach the tree dump. They're compared at source level instead: the FORMAT text extracted
    from the `.m` (independent extractor, §7.3) vs from the `.F90`, under the same whitespace rule. They're dead code, so they can't affect the
    program or the numbers, but they are checked anyway.
  - The check runs on the serial build. No FORMAT or WRITE lies inside an `#ifdef _OPENMP` branch today; the check fails if one ever does.
- **Secondary check, preprocessing:** the merged reference and the `.F90` each preprocess cleanly with and without `-fopenmp`. OpenMP sentinel
  lines (`!$`, `c$`, `*$`) are compared as code. The sources have none today, and the gate fails if one appears on one side only.
- **BASIS branch removal:** `com/error.f` (`gfortran -E -DFORTHON`) and `bbb/exmain.c` (`cc -E -DFORTHON`) preprocess identically before and after.
- **Negative controls (must fail), on real sources:** a sign flip, a dropped `#ifdef _OPENMP` branch, `#ifdef`↔`#ifndef` swapped, a changed
  character in a continued string, a dropped `use`, a split keyword token, a label moved to another statement, a changed Hollerith count and a
  changed edit descriptor in a real FORMAT (`svr/svrut1`), and a changed blank inside Hollerith data.
- No object-file comparison.

### 7.3 `tools/check_comment_fidelity.py` (comment gate)
- Compares the **`.m` source** with the **committed `.F90`** directly, and also the `.m` with the fixed-form reference, so a stage 1 vs stage 2 loss is localised.
- Records `(routine, kind, exact text after the marker, following-code anchor)`. Kind is full-line or inline. Runs on raw source, never on `-E` output.
- **Independent extraction:** the `.m` side is read by a separate, line-based extractor that knows no column limit and shares no code with the
  converter's lexer. That way a lexer error, such as truncating the 5 comments that run past column 132, can't cancel out on both sides.
- Passes when there are 0 unexplained missing, extra, altered or relocated comments, and the exception list matches exactly.
- **Independent cross-check:** a second, minimal implementation (per-routine comment-line and inline-comment counts) whose totals must agree.
- **Negative controls (must fail):** on the output side, a reworded comment, a deleted comment, a comment moved to another routine,
  inline↔full-line, a comment lost inside a continued statement, and an unlisted exception; on the **input side**, a comment truncated at
  column 132 and a dropped indented comment-only line.

## 14. Risks & Mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| The fixed→free converter changes meaning (blank-insensitive tokens, string padding, Hollerith, labels) | Silent behaviour change | Gate 1 compares parse trees in both builds against the fixed-form reference. Negative controls for each construct. A Phase 0 pilot on `wdf` |
| The parse-tree dump isn't form-independent or omits detail | Gate 1 can't be trusted | Proven in Phase 0 with negative controls. Fallback: a form-aware token comparison |
| A comment is lost (MPPL substitution, reordering, a continuation rewrite, a lexer bug) | Loss of in-source documentation | Comment pass; the fidelity gate compares `.m` directly with `.F90`; exact exception list; independent cross-check; negative controls |
| Long lines after adding `&` | Compile errors, or a flag change | Re-wrapping at token boundaries; the ≤ 132 criterion |
| The `#ifdef _OPENMP` merge differs from what a build compiles today | Silent change in serial or OpenMP | Unmodified converter per build, a `diff -D` merge, and gate 1 in both builds |
| The equivalence gates can't fail | False confidence | Negative controls for every gate. The reference comes from the parent commit, not a self-comparison |
| v8 backports stop applying | Fixes diverge | Permanent freeze tool with a backport mode through both stages. **Owner:** v9 maintainer, agreed with the v8 maintainers in Phase 0 |
| Grid-generation coverage is lost with BASIS CI | A `flx`/`grd` regression goes unnoticed | The `gengrid=1` case lands before `build-basis.yml` is deleted |
| History and blame lost (rename + form change + re-indent) | Archaeology gets harder | Separate rename and freeze commits, rebase-merge, `.git-blame-ignore-revs` |
| A leftover generated `.F` is compiled instead of the `.F90` | Edits silently ignored; gate 2 passes vacuously | `clean` deletes `<pkg>/*.F`; `setup.py` refuses to build while an `x.F` sits next to an `x.F90`; gate 2's after-run uses a fresh worktree; negative control |
| A FORMAT change is invisible to the parse-tree gate | Wrong output formats | A dedicated FORMAT check on compiled format strings, independent of the converter, with negative controls on real FORMATs |
| `.m` PRs merged during the epic are left behind | Lost fixes | `.m` code-freeze window. The reference is the parent commit |
| Tolerant restore hides a real problem | A partial restore | It only skips variables that don't exist and prints one warning listing them. `hdf5_restore` stays strict |
| Someone relies on PETSc, PACT or BASIS | Lost capability | Release notes. The last pre-AIUE-5 tag. LLNL confirms in Phase 0 |
