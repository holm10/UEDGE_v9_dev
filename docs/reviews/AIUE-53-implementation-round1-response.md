# AIUE-53 implementation review, round 1: response

Review: `docs/reviews/AIUE-53-implementation-round1.md` (REVISE: 1 blocker, 2 major, 7 minor). Every finding is
fixed. Before the fixes, the branch was rebased onto `feature/v9-AIUE-49-omp-harness-core` at 71b0e3b. That tip brings
two things: raw AIUE-47 captures in `worker.py`, and the stricter `compare_records` (`check_arm`, record checks,
`cli.exit_code`). It also renames `full_note` to `te_phi`. The validation results are appended to
`docs/reviews/AIUE-53-validation.txt` (round 2).

| **I1-B1 (BLOCKER):** the solver path is never run, and the fnrm sequence has one element | **Fixed.** Ten Newton-iteration cases were added. They run N iterations at the deck's `ftol`, so `psetnk`, ILU, Krylov and the line search run. The full `fnrm` sequence (4–6 elements), the final `yldot`/`fnrm` and every Jacobian are compared. The cases are `repro-tebox-it5`, `repro-te-it3`, `repro-full-it3` and `pytests-{D_only,D+C,D_mols,full-d_c-16x8,slab}-it5`; `quick` has `repro-tebox-it5` and `pytests-{D_only,D+C}-it5`. `pytests_worker.py` has an `itermx` mode: the final `exmain` runs at the `ftol` that `input.py` left. Both workers capture every `sfsetnk`/`psetnk` raw Jacobian when both builds have the hook. Results: the independent-build gate agrees on all of them (`iters 4`/`iters 6`, `post(psetnk)`). With both hooks, AIUE-47 against itself compares `2+post(psetnk)` Jacobians. The negative control and the ulp control both fail on them. | `serial_check.py` CASES/QUICK/ALL, `pytests_worker.py`; validation §R2-1, R2-3, R2-4, R2-5 |
| **I1-M1:** RESULT AGREE / exit 0 on a partial or self comparison | **Fixed.** The gate is complete only with both pairs, base and new different builds, and every case of `all` (now the default). Anything less that agrees prints `RESULT: INCOMPLETE (what ran agrees bitwise; not the gate)`, adds `NOT THE GATE:` lines listing what was skipped, and exits 2. `--partial-ok` turns that into exit 0, with `RESULT: AGREE, PARTIAL (--partial-ok; not the gate)`. The RESULT line always names the pairs and the case set. The JSON has `gate_complete`, `incomplete`, `skipped_pairs` and `skipped_cases`. The docs say only `RESULT: AGREE (bitwise identical; complete gate)` meets the gate. | `serial_check.py` `serial_check`, `result_line`; README, `testing.md`, `openmp-jacobian.md`; validation §R2-2 |

These are printed per build and stored in the JSON. Harness errors (overridable with `--allow-same-build`, which makes the run incomplete): the same source tree, or the same clean commit. Warnings: a base not on `origin/v9-develop`, an unknown source, a dirty tree, serial and OpenMP builds from different commits. In addition, every record's `provenance.build.extensions_sha256` must equal the probed one, so a venv reinstalled during the check is a harness error. Not changed:
- **The final `yl` is not recorded separately.** In an iterating case the final `yldot` (every equation, bit for bit), the final `fnrm`, the printed sequence and the last `psetnk` Jacobian are all functions of the final `yl`. A `yl` difference that leaves all of them bitwise equal is not realistic, and recording `yl` would mean changing the shared `worker.py`.
