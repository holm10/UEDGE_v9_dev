| **R1-M1** (MAJOR) failure under `--itermx 3` names a downstream cell | **Fixed, option (b).** The PR set now starts with `tebox1`: Te box, `jac`, 2 and 4 threads, K=3, **one evaluation** (no `--itermx`), gated like the other flows. Its post-`exmain` Jacobian is in natural order, so the first mismatch is the defect cell. `report.py` prints a job-level `FIRST MISMATCH` line, taken preferably from a one-evaluation group. An `--itermx 3` group whose first mismatch sits at permuted positions cites the one-evaluation group of the same configuration, arm and threads (`located by the one-evaluation group [tebox1]: ...`). Without one, it gives the first cell-mapped entry, explicitly labelled `may be downstream of the defect`, and that entry is never used for the headline. The `--itermx 3` flows stay in for the Newton path. A flow spec has a sixth field, `itermx` (`none` means one evaluation). The nightly set gains `all1` (`--all`, one evaluation, K=2). On the AIUE-56 build the headline names `te(ix=4,iy=20)` (section 8). The budget was re-estimated at 14–20 min, central ~17. The extra flow costs under 1 min on CI (7 runs of ~1.5 s each here). |
| **R1-M2** (MAJOR) merge precondition understated | **Fixed.** The workflow header, the README banner, `testing.md` and the plan now state the full condition. Merge only after AIUE-56 **and** once the gate can be green on that code: after decision 9 (a tolerance gate) or AIUE-61 (C2/M2 removed; an OpenMP-only replay remedy is being prototyped). Merged earlier, the job would turn every push and pull request red. "Green on the fixed code" stays an open acceptance item. Section 8 confirms the AIUE-56 build is red under the bitwise gate. |
| R1-m1 tolerance switch under `--itermx 3` | **Fixed (README, workflow comment).** A Jacobian-only tolerance is not enough under `--itermx 3`, because `yldot`, `yldot_probe` and `fnrm` also differ. Two ways out: the comparator also covers those sections, or the gated flows are the one-evaluation ones and the `--itermx 3` flows become report-only. The "no other file has to change" claim is removed. |
| R1-m2 no `permissions:` | **Fixed:** `permissions: contents: read`. |
| R1-m3 duplicate runs, cancelled default-branch runs | **Fixed.** `push` is limited to `v9-develop` and `main`; other branches run through `pull_request` only. `cancel-in-progress: ${{ github.event_name == 'pull_request' }}`, so pushes and scheduled runs always finish. The ticket's push and pull_request triggers are both still there. |
| R1-m4 "≥ 3 Newton iterations" not enforced | **Fixed in `report.py`.** For an `--itermx N` flow, every serial reference's `record.json` must show `max(iterations[].iter) >= N`; otherwise the result is exit 2 (cannot judge). An OpenMP run that iterates differently already fails `fnrm_printed`. Unit-tested, and checked on the real runs (Te box and full: 3 iterations, section 8). |
