4. Gate design and the decision-9 switch
----------------------------------------
- Gate = the flow's own jac-arm verdict (`--gate jac`), bitwise. Exit 1 on a mismatch, exit 2 when the flow cannot
  judge (failed serial reference, arm not in effect, unit/smoke test failed). jacrhs: ::warning:: only.
- One switch: OMP_CI_JAC_TOLERANCE in the workflow env. Empty = bitwise. A value is forwarded as
  `--jac-tolerance VALUE` once harness/cli.py flow has that option; until then the script stops with exit 2 and a
  message (checked, section 1). No tolerance comparator was written here. Option name is a proposal for the
  harness ticket; if it lands under another name only run_omp_ci.sh (two lines) changes.

Flow scheduling with --cores 4 --max-jobs 4 (harness/flow.py _schedule): the serial reference (1 core) starts
first, a 2-thread run fits beside it, 4-thread runs wait until the 4 cores are free.

  tebox flow: 1 serial + 20 OpenMP runs  1.5-3 min  (21 runs x 4-8 s; t4 runs exclusive, t2 runs in pairs)
