4. Gate design and the decision-9 switch
----------------------------------------
- Gate = the flow's own jac-arm verdict (`--gate jac`), bitwise. Exit 1 on a mismatch, exit 2 when the flow cannot
  judge (failed serial reference, arm not in effect, unit/smoke test failed). jacrhs: ::warning:: only.
- One switch: OMP_CI_JAC_TOLERANCE in the workflow env. Empty = bitwise. A value is forwarded as
  `--jac-tolerance VALUE` once harness/cli.py flow has that option; until then the script stops with exit 2 and a
  message (checked, section 1). No tolerance comparator was written here. Option name is a proposal for the
  harness ticket; if it lands under another name only run_omp_ci.sh (two lines) changes.


5. PR-job time estimate (ubuntu-latest, 4 vCPU, 16 GB)
-------------------------------------------------------
Inputs: AIUE-54 (macOS, loaded, upper bounds): Te box one run 2-6 s; full serial one evaluation 35-55 s; full
OpenMP 4 threads one evaluation 11-13 s; full comparison ~5 s; itermx 3 x2-4. Measured here at the end, load ~15-25:
full serial one evaluation 38.2 s, full serial --itermx 3 99.3 s (x2.6), full jac 4 threads --itermx 3 46.3 s.
Te box --itermx 3 runs 4-10 s at load ~90 (3b), one evaluation 1.3-3.4 s (3e).
Assumed: a runner core is 1.5-2x slower than this machine's cores; the OpenMP build takes 4-7 min (not measured
in CI; the two local scratch builds took a few minutes each under load 60+).

Flow scheduling with --cores 4 --max-jobs 4 (harness/flow.py _schedule): the serial reference (1 core) starts
first, a 2-thread run fits beside it, 4-thread runs wait until the 4 cores are free.

  step                                   estimate
  checkout, setup-python, pip deps       ~1 min
  pip install -v . (OpenMP)              4-7 min
  unit tests + smoke test                < 0.5 min
  tebox flow: 1 serial + 20 OpenMP runs  1.5-3 min  (21 runs x 4-8 s; t4 runs exclusive, t2 runs in pairs)
  full flow (jac only):                  6.3-8.8 min
     serial (1 core)                                 150-200 s   (99 s here x 1.5-2)
     2 x t2, one after the other, beside it          210-280 s   (t2 not measured: ~1.5 x t4, x 1.5-2)
     then 2 x t4 (need all 4 cores)                  140-186 s   (46 s here x 1.5-2, each)
     6 comparisons (4 agreement, 2 determinism)      30-60 s
  report + artifact upload               < 0.5 min
  TOTAL                                  ~14-21 min, central ~17 min

The upper end crosses the 20-min budget only if every factor is at its worst. That is why the full-problem jacrhs
arm (report-only, ~40 % of the full flow) is not in the PR set; the nightly set runs it. Further cuts, in order,
if the measured time is over 20 min: tebox K 5 -> 3; full at 4 threads only. Job timeout 30 min.
