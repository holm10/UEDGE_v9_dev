| **I2-M1 (MAJOR):** "complete gate" and exit 0 even when the source guard could not run, or found a base that is not v9-develop | **Fixed.** `check_pair` now returns a fourth list of *gate* issues, and each one adds an item to `result["incomplete"]`. That gives `RESULT: INCOMPLETE … (not the gate: <reasons>)` with exit 2, or `AGREE, PARTIAL (--partial-ok) … (not the gate: <reasons>)` with exit 0. The RESULT line names the reasons as short tags, and the `NOT THE GATE:` lines give the full text. The gate issues are: (1) an unknown source on either side (no `direct_url.json`, a `.whl` URL, a directory that is gone or not a git checkout); (2) a base HEAD that is not `origin/v9-develop` or an ancestor of it, or whose ancestry check failed; (3) **a dirty tree, or one whose dirty state could not be read** (see below); (4) a stale build (I2-m1). The reviewer's five fake states, plus a stale-build state, are unit tests (`test_source_guard_states_are_not_the_gate`). Each asserts exit 2 with the named reason, and exit 0 with `AGREE, PARTIAL` naming it under `--partial-ok`. Stacked-branch comparisons still work through `--partial-ok`. | `serial_check.py` `check_pair`, `result_line` (`INCOMPLETE_TAGS`); `test_serial_check.py`; README "Build and source guard", `testing.md`, `openmp-jacobian.md` |
| *Decision on dirty trees* | **Dirty trees are INCOMPLETE, not a warning.** A dirty tree contradicts "build from clean committed trees". The recorded HEAD then does not identify what was built, so the PR evidence cannot be reproduced. Scratch builds (negative controls, work in progress) are uncommitted on purpose. They still report MISMATCH and exit 1, because a mismatch is never hidden by an incomplete gate, and an agreeing scratch run is `AGREE, PARTIAL` under `--partial-ok`. When base and new are the same commit and differ only by uncommitted changes, that is still a warning in addition. | as above |
| **I2-m1:** the HEAD read at check time can name the wrong commit | **Fixed.** `build_probe.py` records `extensions_mtime`, the latest mtime of the installed extension modules. `source_info` records `head_time`, the HEAD commit time. A build whose HEAD was committed after its extensions were written is *stale*. That is a gate issue ("the recorded HEAD may not be what was built (reinstall)"), not just a warning, for the same reason as a dirty tree. When either build of a role is stale, the "serial and OpenMP builds come from different commits" warning is replaced by one that says the builds may well contain the same code. Tests: `test_stale_build`, and the `"new built before its HEAD"` state in the parametrised test. The round-3 run base vs AIUE-47 shows it live, since the AIUE-47 trees have commits newer than their builds. | `build_probe.py`; `serial_check.py` `is_stale`, `check_pair`, `serial_check()` |

Both records must show at least 2 printed iterations and `post_exmain_from == "psetnk"`. Otherwise the case is an ERROR naming the role, the count and the source, with exit 2. Tests: `test_iteration_problems`, and `test_main_case_that_did_not_iterate_is_error` (a whole run in which the `-it` records show one iteration).
